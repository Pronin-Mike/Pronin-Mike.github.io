# Ручное использование продукта

Операция реализована миграцией
[`20261020101721_consume_product.sql`](supabase/migrations/20261020101721_consume_product.sql)
и подключена к сценарию «Использовать».

## RPC

```sql
public.consume_product(
  p_item_id uuid,
  p_amount numeric,
  p_operation_id uuid
) returns jsonb
```

Функция в одной транзакции:

1. Проверяет `auth.uid()`, идентификаторы и положительное количество.
2. Регистрирует `operation_id` в приватной `app_private.consume_operations`.
3. При повторе сверяет пользователя, продукт и количество. Идентичный повтор возвращает
   сохранённый JSON, другие аргументы дают `Operation id conflict`.
4. Блокирует остаток через `select ... for update`. Та же блокировка используется
   `waste_product` и `cook_dish`, поэтому конкурирующие списания сериализуются.
5. Пропорционально списывает `total_cost` и `priced_amount` по действующей модели.
6. Записывает движение `consume` / `manual_use` до возможного удаления остатка.
7. Уменьшает позицию или удаляет её полностью.

Ответ:

```json
{
  "success": true,
  "operation_id": "uuid",
  "amount": 300,
  "remaining_amount": 700,
  "cost": 60,
  "cost_complete": true
}
```

## Почему используется отдельная таблица идемпотентности

`product_movements.operation_id` нельзя сделать уникальным: одна операция `cook_dish`
намеренно создаёт несколько движений. Кроме того, после полного расхода внешний ключ
`fridge_item_id` становится `null` по `ON DELETE SET NULL`, поэтому одной исторической строки
недостаточно для проверки исходных аргументов повтора.

`app_private.consume_operations` недоступна `PUBLIC`, `anon` и `authenticated` напрямую.
Доступ к ней имеет только `SECURITY DEFINER` RPC с фиксированным `search_path`; вызов RPC
разрешён `authenticated` и `service_role`.

## Модель доступа

Текущая схема приложения хранит общий холодильник: в `fridge_items` нет `owner_id`, а RLS
разрешает чтение всех позиций роли `authenticated`. Поэтому `consume_product` соответствует
существующей модели и проверяет аутентификацию, но не может доказать персональное владение
конкретной строкой. Настоящее разделение холодильников по пользователям потребует отдельной
миграции `owner_id`, безопасного backfill и обновления всех политик и RPC.

## Проверка

На подключённой базе выполнен транзакционный тест с последующим `rollback`: частичное и
полное списание, стоимость, история, идентичный повтор и конфликт аргументов прошли успешно.
Тест не оставил продукты или движения в production-данных.
