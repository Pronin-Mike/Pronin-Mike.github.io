# 🍳 Домашняя кулинарная книга.

Персональная кулинарная книга: рецепты по разделам, холодильник с продуктами и честный
ответ на вопрос «что можно приготовить прямо сейчас». Данные живут в **Supabase**
(PostgreSQL + Auth + RLS), сайт — чистая статика на **GitHub Pages**, своего бэкенда нет.

**Стек:** React 18 · Vite 5 · TypeScript (strict) · TailwindCSS 3 · @supabase/supabase-js ·
react-router-dom (HashRouter) · lucide-react.

---

## Быстрый старт

```bash
# 1. зависимости
npm install

# 2. ключи Supabase
cp .env.example .env.local     # Windows: copy .env.example .env.local
#   вписать VITE_SUPABASE_URL и VITE_SUPABASE_ANON_KEY
#   (Supabase → Project Settings → API)

# 3. разработка
npm run dev                    # http://localhost:5173
```

Пользователей регистрация не создаёт: аккаунт заводится вручную в
**Supabase → Authentication → Users → Add user** (email + пароль), затем вход на `/login`.

### Скрипты

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер Vite |
| `npm run build` | `tsc --noEmit` + сборка в `dist/` |
| `npm run preview` | локальный просмотр собранного `dist/` |
| `npm run typecheck` | только проверка типов |
| `npm test` | unit- и интеграционные тесты (vitest) |

Если переменные окружения не заданы, сайт не падает, а показывает экран с инструкцией,
что именно нужно прописать.

## Что умеет

**📖 Рецепты (`/`)** — разделы приходят из таблицы `sections` (Завтрак, Обед, Ужин) плюс
вкладка «Все». Поиск по названию блюда и по ингредиентам, переключатель
**«Что приготовить»** оставляет только полностью доступные блюда. Карточки: активная —
с кнопкой «Приготовить»; недоступная — серая (`opacity-50`) с бейджем
«Не хватает: …», внутри неё кнопка заблокирована, но рецепт открывается для просмотра.

**🍲 Блюдо (`/:sectionId/:dishId`)** — ингредиенты с отметками «есть / не хватает», шаги,
заметки, кнопки «Приготовить», «Редактировать», «Удалить» (с подтверждением).

**➕ Блюдо (`/dish/new`, `/dish/:id/edit`)** — динамические списки ингредиентов и шагов,
раздел, время, заметки. При сохранении ингредиенты перезаписываются целиком.

**🧊 Холодильник (`/fridge`)** — быстрое добавление, правка, удаление, поиск, сортировка по
названию, «Очистить холодильник» с подтверждением. Если продукт с таким названием и
единицей уже есть — предлагается **Заменить / Сложить / Отмена**.

**📥 Импорт (`/import`)** — блюда из CSV с предпросмотром таблицы и списком ошибок по
строкам; JSON-бэкап (экспорт и полная замена базы с подтверждением).

**⚙️ Настройки (`/settings`)** — email пользователя, экспорт JSON, выход.

Дизайн: тёплые бежевые тона, терракотовые и оливковые акценты, скруглённые карточки,
фотографий нет — вместо них эмодзи разделов (🍳 завтрак, 🍲 обед, 🍽 ужин). Мобильная
версия приоритетна: нижняя навигация, шторки-модалки, тач-таргеты от 44px. Тосты
автоскрываются через 3 секунды (ошибки — через 5).

## Схема Supabase, которую ожидает фронтенд

Схема уже создана; клиент только читает и пишет в неё. Ожидается:

| Объект | Что используется |
|---|---|
| `sections` | `id text`, `title_ru text`, `sort_order int`; строки: `breakfast/Завтрак`, `lunch/Обед`, `dinner/Ужин` |
| `fridge_items` | `id uuid`, `name text`, `amount numeric`, `unit text`, `updated_at`; ограничения `unique (name, unit)`, `unit in ('г','мл','шт')`, `amount >= 0` |
| `dishes` | `id uuid`, `title`, `section_id → sections.id`, `time_min int null`, `steps text[]`, `notes text`, `created_at`, `updated_at` |
| `dish_ingredients` | `id uuid`, `dish_id → dishes.id on delete cascade`, `name`, `amount numeric`, `unit`, `sort_order int` |
| `cook_log` | `id uuid`, `dish_id → dishes.id on delete set null`, `cooked_at` |
| view `dishes_full` | `id, title, section_id, time_min, steps, notes, ingredients` |
| функция `cook_dish(p_dish_id uuid)` | `returns jsonb` |

Что важно для корректной работы:

* **`dishes_full.ingredients`** — jsonb-массив объектов вида
  `{"name": "сыр", "amount": 50, "unit": "г", "sort_order": 0}`.
  Клиент понимает и массив, и строку JSON, а при недоступности view тихо переключается на
  выборку из `dishes` + `dish_ingredients`, поэтому книга работает в любом случае.
* **`cook_dish`** возвращает `{"success": true}` после успешного списания либо
  `{"success": false, "missing": [{"name": "сыр", "need": 50, "have": 0, "unit": "г"}]}`.
  Ключ `amount` вместо `need` тоже принимается.
* **RLS** включён на всех таблицах, политики разрешают работу только роли `authenticated` —
  поэтому без входа запросы вернут пусто/ошибку, а интерфейс отправит на `/login`.
* Разделов ровно три: `breakfast`, `lunch`, `dinner`. Импорт блюда с разделом `snack`
  («полдник») отклоняется с понятной ошибкой.

## Формат CSV для импорта блюд

```csv
title,section,ingredients,time,steps,notes
Омлет с сыром,breakfast,яйца|3|шт;сыр|50|г;молоко|50|мл,15,"Взбить яйца;Добавить сыр;Обжарить",Солить в конце
```

* `section` — `breakfast` | `lunch` | `dinner` (можно по-русски: завтрак, обед, ужин);
* `ingredients` — элементы через `;`, каждый в формате `название|количество|единица`
  (единицы: `г`, `мл`, `шт`; латиница `g`, `ml`, `pcs` тоже понимается);
* `steps` — шаги через `;`;
* `time` — минуты, можно пусто;
* разделитель колонок определяется автоматически (`,`, `;`, табуляция), заголовки
  понимаются и по-русски (`название`, `раздел`, `ингредиенты`, `время`, `шаги`, `заметки`);
* если количество записано с запятой (`1,5`), берите поле в кавычки или используйте `;`
  как разделитель колонок.

Перед импортом показывается таблица «что будет добавлено» и список ошибок с номерами строк;
строки с ошибками пропускаются. Пример: `public/examples/sample-recipes.csv`
(доступен на сайте как `examples/sample-recipes.csv`).

## JSON-бэкап

`{"app":"home-cookbook","version":1,"exportedAt":"…","fridge_items":[…],"dishes":[…],"dish_ingredients":[…]}`

Экспорт — кнопка в «Импорт» или «Настройки». Импорт полностью заменяет базу: сначала
удаляются блюда (каскадом ингредиенты) и холодильник, затем данные вставляются заново,
идентификаторы генерируются новые, связи «блюдо → ингредиенты» сохраняются.
Пример для проверки: `public/examples/sample-backup.json`.

## Деплой на GitHub Pages

### Вариант 1 (рекомендуется): GitHub Actions

1. Запушьте репозиторий в ветку `main`.
2. **Settings → Secrets and variables → Actions** добавьте:
   * `VITE_SUPABASE_URL`
   * `VITE_SUPABASE_ANON_KEY`
3. **Settings → Pages → Source: GitHub Actions.**
4. Workflow `.github/workflows/deploy.yml` сам прогонит `typecheck`, тесты и сборку,
   подставив `VITE_BASE_PATH=/<имя-репозитория>/`, и опубликует `dist/`.

### Вариант 2: вручную

```bash
# project site: https://<логин>.github.io/<репозиторий>/
VITE_BASE_PATH=/<репозиторий>/ npm run build
npx gh-pages -d dist          # или залейте содержимое dist/ в ветку gh-pages
```

**Про `base`.** Vite кладёт статику по пути `/assets/…`, поэтому для project site нужен
префикс с именем репозитория — иначе браузер запросит файлы из корня домена и получит 404.
В `vite.config.ts` значение читается из `VITE_BASE_PATH` (по умолчанию `/` — это случай
user site `https://<логин>.github.io/`). Можно и просто вписать нужный путь в
`vite.config.ts` вместо переменной.

**Про прямые ссылки.** Приложение использует `HashRouter`, поэтому адреса выглядят как
`…/home-cookbook/#/fridge`, и обновление страницы или переход по прямой ссылке не даёт 404
(статика на Pages не умеет отдавать `index.html` для произвольных путей).

Секреты в бандл не попадают «по-настоящему»: `VITE_*` вшиваются в JS при сборке, но
`anon key` для этого и предназначен — доступ к данным закрывают RLS-политики. Класть в
репозиторий стоит только `.env.example`; `.env.local` в `.gitignore`.

## Правила доступности и приготовления

1. Название сравнивается без учёта регистра и лишних пробелов (`lower(name)` + `unit`).
2. Единица измерения должна совпадать точно: `г`, `мл` и `шт` между собой не пересчитываются.
3. Количество в холодильнике должно быть не меньше требуемого.
4. Никаких синонимов: если в рецепте «масло 30 г», а в холодильнике «масло 200 мл» —
   блюдо недоступно и попадёт в серые карточки с пометкой о нехватке.
5. Кнопка «Приготовить» вызывает серверную функцию `cook_dish`: она проверяет наличие,
   списывает продукты, удаляет обнулившиеся позиции и пишет запись в `cook_log`.
   Если чего-то не хватает, приходит `success: false` со списком `missing` — интерфейс
   покажет его в тосте.

## Частые вопросы

**«Нужны ключи Supabase».** Не заданы `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`
(локально — `.env.local`, на Pages — секреты Actions). После правки перезапустите
`npm run dev` или пересоберите сайт: переменные вшиваются на этапе сборки.

**Вход не проходит.** Пользователь должен существовать в Supabase Authentication → Users.
«Invalid login credentials» — неверная пара email/пароль; «Email not confirmed» —
подтвердите пользователя в панели.

**Пустой список рецептов после входа.** Проверьте, что политики RLS разрешают `authenticated`
доступ к таблицам и view, а в `sections` есть три строки — разделы берутся из базы.

**Сборка падает на `base`.** Для project site нужен `VITE_BASE_PATH=/<репозиторий>/`
(в workflow он подставляется сам).
